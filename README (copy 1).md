# FADIL TRADING — مشروع مستقل

نسخة مستقلة قابلة للتشغيل محلياً لمنصة التداول التعليمية. تحتوي على واجهة عربية RTL، وواجهة إدارة، وواجهة API باستخدام Express، وقاعدة PostgreSQL تُهيّأ تلقائياً عند بدء الخادم.

## المتطلبات

- Node.js 20 أو أحدث.
- PostgreSQL 14 أو أحدث، وقاعدة بيانات مخصصة لهذا المشروع.
- اتصال شبكة بقاعدة البيانات.

## التشغيل المحلي

1. أنشئ قاعدة PostgreSQL جديدة باسم `fadil_trading`.
2. أنشئ ملف الإعداد المحلي من القالب ثم حدّث رابط قاعدة البيانات. لا تستخدم قاعدة تطبيق أخرى؛ يشغّل هذا المشروع مخططه الخاص:

   ```sh
   cp .env.example .env
   ```

   ثم افتح `.env` واكتب رابط الاتصال في `DATABASE_URL`. لا ترفع `.env` إلى Git أو إلى أي مكان عام.
3. ثبّت الحزم وشغّل الخادم:

   ```sh
   npm install
   npm start
   ```

4. افتح `http://localhost:3000`. تهيّئ `server.js` الجداول الأحد عشر وتضيف حساب المدير والدورات الافتراضية إذا لم تكن موجودة.

## حساب المدير

في التشغيل المحلي (`NODE_ENV=development`) ينشئ الخادم حساب المدير:

- اسم المستخدم: `admin`
- كلمة المرور الابتدائية: `123456`

غيّر كلمة المرور قبل نشر الموقع. في `NODE_ENV=production` يجب توفير `ADMIN_PASSWORD` من مدير الأسرار في خدمة الاستضافة؛ يرفض الخادم تشغيل كلمة المرور الافتراضية في الإنتاج.

## الملفات ورفع المحتوى

### Replit

يستخدم الخادم Replit App Storage عند توفر إعداداته في البيئة. تنقل المتصفحات الملفات مباشرة إلى مخزن خاص باستخدام رابط رفع مؤقت؛ لا تُحفظ الملفات في مجلد التطبيق. قاعدة البيانات تحتفظ بمراجع داخلية فقط، والتنزيل يمر عبر API بعد التحقق من الصلاحيات، بما في ذلك ملفات الفيديو وإثباتات الدفع.

في مساحة Replit، جهّز App Storage من أداة التخزين؛ تُضاف إعداداته إلى بيئة التشغيل تلقائياً. لا تضع قيم `DEFAULT_OBJECT_STORAGE_BUCKET_ID` أو `PRIVATE_OBJECT_DIR` في الملفات أو المستودع. يتطلب الوصول المباشر إلى هذه الخدمة تشغيل الخادم داخل Replit.

عند تفعيل App Storage، ينقل الخادم تلقائياً مراجع الملفات المحلية القديمة إلى التخزين الخاص إذا كانت الملفات لا تزال موجودة في `UPLOADS_DIR` أو `uploads/`، ثم يحدّث مراجع قاعدة البيانات. اترك مجلد الملفات القديم متاحاً إلى أن يكتمل بدء التشغيل الأول بعد التفعيل.

### استضافة أخرى

في الاستضافات التي توفر وحدة تخزين دائمة مركّبة، عيّن `UPLOADS_DIR` إلى مسار تلك الوحدة. تبقى Multer والواجهة الحالية مستخدمتين، لكن الملفات تُكتب في المسار الدائم بدلاً من مجلد المشروع. لا تضبطه إلى مجلد مؤقت أو إلى مجلد النشر الذي يُستبدل عند كل إصدار.

في `NODE_ENV=production` يرفض الخادم البدء إذا لم يُهيّأ Replit App Storage ولم يُضبط `UPLOADS_DIR`. محلياً، عند عدم تهيئة التخزين، تُحفظ الملفات في `uploads/` للتطوير فقط. لا تخدم المجلد مباشرةً؛ تمر التنزيلات عبر API وتُطبّق عليها صلاحيات الطالب والدورة والإدارة.

## الجداول

ينشئ `initDatabase()` الجداول: `users`, `courses`, `lessons`, `resources`, `quiz_files`, `result_files`, `progress`, `subscriptions`, `messages`, `news`, `analyses`. بيانات الجلسة الموقعة تحفظ كـ hash ووقت انتهاء داخل جدول `users` حتى يبقى العدد الإجمالي 11.

## الاستضافة

تستخدم الاستضافة أمر `npm start` أو السطر الموجود في `Procfile`. اضبط `DATABASE_URL` و`NODE_ENV=production` و`ADMIN_PASSWORD` كمتغيرات بيئة/أسرار من لوحة الاستضافة، وليس داخل المستودع. على استضافة غير Replit، اضبط أيضاً `UPLOADS_DIR` لمسار وحدة التخزين الدائمة. في Replit، استخدم App Storage ولا تنسخ قيم إعداداته إلى `.env`.
